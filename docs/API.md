# API Reference

> Written 2026-09-15, read directly from `backend/api/*.py` and `backend/schemas/*.py`. All routes
> are mounted under the `/api/v1` prefix (`backend/main.py`) except `/health`. Interactive docs are
> also auto-generated by FastAPI at `/docs` whenever the API is running.

## Authentication

Every route below except `/health`, `POST /auth/register`, and `POST /auth/login` requires
`Authorization: Bearer <JWT>`. The WebSocket route is the one exception to the header rule — it
takes the token as a `?token=<JWT>` query parameter instead, since the WebSocket handshake can't
carry a custom header from a browser or Flutter's WS client.

## `POST /api/v1/auth/register`
Body (JSON): `{"email": str, "password": str (8–72 chars)}`. Returns `201` + `{"id", "email",
"created_at"}`. `409` if the email is already registered.

## `POST /api/v1/auth/login`
Body: OAuth2 password form (`username`=email, `password`). Rate-limited (`10/minute` default).
Returns `{"access_token": str, "token_type": "bearer"}`. `401` on bad credentials.

## `POST /api/v1/transcribe`
Whole-file upload. `multipart/form-data`: `file` (the audio), `consent_confirmed` (required bool),
`title` (optional), `enable_denoise`/`enable_vad`/`enable_diarization`/`enable_teacher_verification`
(bools), `num_speakers` (optional int), `beam_size` (default 5). Rate-limited (`30/minute`).
Returns `202` + `{"session_id": str, "status": "processing"}` immediately — the client polls
`GET /sessions/{id}` until `status` is no longer `"processing"`.

## `WS /api/v1/ws/transcribe?token=<JWT>`
The streaming path. Protocol, in order:
1. Client sends the first message: `{"type": "start", "title": str|null, "options": {...
   PipelineOptions}, "consent_confirmed": bool}`.
2. Server replies `{"type": "session_started", "session_id": str}`, or `{"type": "error",
   "detail": str}` + closes if the start frame was invalid.
3. Client streams binary WebSocket frames, each a complete, self-contained WAV file (one per
   chunk).
4. Server sends `{"type": "chunk_result", "chunk_index": int, "text": str, "language": str|null,
   "whisper_segments": [...], "speaker_segments": [...], "transcript_so_far": str}` as each chunk
   finishes processing (order not guaranteed to match send order — `transcript_so_far` is always
   the correct contiguous view regardless), or `{"type": "error", "chunk_index": int, "detail":
   str}` for a chunk that failed (non-fatal — the session continues).
5. Client sends `{"type": "end"}` when done recording.
6. Server sends one final `{"type": "session_ended", "session_id": str, "transcript": str,
   "keywords": [str], "minutes": {...}|null}`, then closes the socket.

Custom close code `4401` = authentication failed (invalid/missing token).

## `GET /api/v1/sessions`
Returns `[{"id", "title", "status", "created_at", "duration_seconds"}, ...]` — every session owned
by the current user, newest first.

## `GET /api/v1/sessions/{session_id}`
Returns the summary fields above plus `consent_confirmed`, `pipeline_options`, `transcript_text`,
`transcript_segments` (list of `{start, end, text, avg_logprob, no_speech_prob, speaker, is_teacher,
teacher_name, confidence}` — the last four keys present only if diarization/teacher-verification
ran), `speaker_segments`, `keywords`, `minutes`, `stage_latencies`. `404` if not found or not
owned by the caller.

## `DELETE /api/v1/sessions/{session_id}`
Full purge. Returns `{"deleted": true}`. `404` if not found/not owned.

## `POST /api/v1/teachers/enroll`
`multipart/form-data`: `name` (str), `file` (the enrollment audio). Rate-limited (`10/minute`).
Returns `202` + `{"id", "name", "status": "pending", "error_detail": null, "created_at"}`.

## `GET /api/v1/teachers`
Returns every teacher enrollment owned by the current user.

## `GET /api/v1/teachers/{teacher_id}`
Returns one enrollment's current status (`pending|ready|failed`), for client-side polling.

## `DELETE /api/v1/teachers/{teacher_id}`
Returns `{"deleted": true}`. `404` if not found/not owned.

## `GET /api/v1/sessions/{session_id}/minutes`
Returns the raw minutes dict: `{"generated_at", "duration_seconds", "participants",
"teacher_speech_ratio", "teacher_speakers", "keywords", "topics": [{"label", "start", "end",
"key_points": [str]}], "definitions": [{"term", "definition", "start", "speaker", "is_teacher"}],
"action_items": [{"text", "start", "speaker"}]}`. `409` if minutes haven't been generated yet
(session not finalized).

## `GET /api/v1/sessions/{session_id}/minutes/export?format=markdown|txt`
Returns the rendered minutes as `text/plain`, with a `Content-Disposition: attachment;
filename="minutes_<id>.<md|txt>"` header. `format` defaults to `"markdown"`; `400` for any other
value. `409` if minutes don't exist yet.

## `GET /health`
No auth required. `{"status": "ok", "environment": "development"|"production"}` — liveness only,
doesn't touch the database or worker tier.

## `GET /metrics`
Prometheus-format metrics (via `prometheus-fastapi-instrumentator`). No auth required — same as
most Prometheus exporter conventions; not something this project has hardened for a public/
untrusted network.

## Not implemented

- No `/sessions/{id}/export` (transcript export) — only minutes has an export route.
- No password-reset, email-verification, or account-management routes beyond register/login.
- No admin/moderation routes — every route is scoped purely to the calling user's own `owner_id`.
