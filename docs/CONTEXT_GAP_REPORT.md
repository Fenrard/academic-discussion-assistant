## Read this first: the two highest-value findings

### 1. An entire substantive editing pass to the thesis manuscript exists nowhere in the repository

Earlier in this session, the actual thesis manuscript (`THESIS [FINAL]_...(1).docx`) was edited
directly — 11 substantive fixes plus 7 copyedit fixes to Chapters 1 and 3, correcting: the
pipeline-order description, LoRA/fine-tuning tense (softened from implying a completed run to
accurately describing an untrained scaffold), a false claim that `python-docx`/Pandas were used
for output generation (corrected to Markdown/plain-text, "Pandas installed but unused"),
diarization-integration wording, an OS/GPU clarification, a Processing-Time-vs-Latency definition
split, several plain typos, and a table-numbering fix (a stray "Table 3" reference corrected to
"Table 2," since the manuscript only has two real tables).

**Classification: NOT RECONSTRUCTABLE.**

**Why:** `.docx` is a binary/zipped format — there is no readable diff even if the file *were*
git-tracked, and it isn't:

```
$ git ls-files | grep -i "thesis\|\.docx"
(no output)
$ git log --all --full-history --oneline -- "*.docx"
(no output)
```

Confirmed directly this pass: **no thesis document has ever been committed to this repository, on
any branch, at any point in its history.** A backup of the pre-edit file does exist on disk
(`THESIS [FINAL] - BACKUP BEFORE AI EDITS 2026-09-16.docx`), but it is also untracked and
un-diffable — recovering "exactly what changed and why" from the two binary files alone would
require manually opening both in Word and comparing them by eye, paragraph by paragraph, with no
record of which paragraph numbers were touched or why.

**What's missing, specifically, if you want to preserve this manually:** a record of the ~18
individual edits — which paragraph, what it said before, what it says now, and why. This
conversation has that record (it was generated by directly reading and rewriting specific
`doc.paragraphs[]` indices via `python-docx`, one edit at a time, verified by re-reading each
changed paragraph after saving). None of it was ever written to a markdown file. If you want this
preserved, the two options are: (a) ask this session (or paste this report into a future one, with
the full paragraph-level detail still in scratchpad/transcript history if recoverable) to write a
`docs/THESIS_EDIT_LOG.md` before the conversation context is lost, or (b) accept that the only
record going forward is a manual diff of the two `.docx` files in Word.

### 2. `CLAUDE.md` contains a factual error about the manuscript's git status, plus a dangling cross-reference

While verifying finding #1, this pass also directly checked `CLAUDE.md`'s own existing claim about
the manuscript file. `CLAUDE.md`'s Directory Map (line 361) says:

> `THESIS_...(4).docx` ... "it's already tracked (see docs/DEVELOPMENT.md for the standing rule
> about it)"

Both halves of this are wrong, confirmed directly this pass:

- **"it's already tracked" is false** — the same `git ls-files`/`git log --all -- *.docx` check

  project's history.
- **The `docs/DEVELOPMENT.md` cross-reference is dangling** — `grep -i "manuscript\|docx"

- **The filename itself is stale** — `THESIS_...(4).docx` does not exist anywhere on disk. The

  Directory Map still names. `CLAUDE.md`'s own "What This Project Is" section (line 387) repeats

**Classification: PARTIALLY RECONSTRUCTABLE.** The *correct* current filename is trivially
reconstructable by anyone who runs `ls` or `git status` in the repo root — but `CLAUDE.md` itself,
read on its own (which is exactly how a cold-start reader is instructed to use it), asserts

fixing directly, not just noting: the fix is a small, mechanical `CLAUDE.md` edit (correct the

job is to identify gaps, not silently rewrite `CLAUDE.md` again outside of what was asked.

### Commands / techniques discovered during development

**One genuinely useful, undocumented technique**, discovered and used repeatedly this session for
validating the three new PowerShell scripts without executing them (and their side effects):

```powershell
$errors = $null; $tokens = $null
[void][System.Management.Automation.Language.Parser]::ParseFile('path\to\script.ps1', [ref]$tokens, [ref]$errors)
if ($errors.Count -gt 0) { $errors | ForEach-Object { Write-Host $_.Message } }
```

This performs a pure syntax check — no execution, no side effects — and is what caught the
em-dash encoding bug before the script was ever run for real. **Classification: NOT
RECONSTRUCTABLE.** Nothing in `docs/SETUP_AUTOMATION.md` or elsewhere records this technique; a
future session editing these `.ps1` files would have to rediscover it (or just run the script for
real and hope side effects are safe). Worth adding to `docs/SETUP_AUTOMATION.md` if PowerShell
script maintenance continues to be a recurring task in this repo.
